# Run 09 · eval pass@4（副协议：能力上界探测）

| 项 | 内容 |
|---|---|
| 日期 | 2026-09-21 |
| 协议 | 4 采样/题（temp=0.7）、40 题 × 2 组 = 320 条轨迹 |
| 结果 | **base pass@4 = 15%（6/40）vs lora = 10%（4/40）**；轨迹级 8/160 vs 8/160（**完全相同**） |
| 状态 | ✅ 完成（链式脚本无人值守跑通，含自动汇总） |

## 目标
区分两种互斥假设：H1"会做但不稳" vs H2"能力断崖"——单次采样无法回答。

## 关键结果（测试的真正价值）
1. **pass@4 (15%) = pass@1 greedy (5%) × 3** → H1 成立：模型"会做但不稳"；
2. **85% 的题 4 次全败（0/4）** → 训练池的绝大多数题**不提供 GRPO 信号**
   （组内全零 = 优势恒 0）——这是 Run 07 训练未提升的直接解释；
3. **轨迹级通过率两组完全相同（8/160）** → 50 步 LoRA 未改变基本能力（最有力证据）。

## 执行中的四轮缺陷链（详见复盘文档）
| 轮 | 失败 | 根因 | 修复 |
|---|---|---|---|
| ① | 单批 160 沙箱只成功 100 | AGS 配额上限 100 截断（后 15 题无数据） | 分批采样（n=2 + `--sample-offset`）+ 批前配额探针 |
| ② | 4 批全部秒失败 | 清单 `nodeName` 硬编码的旧节点被释放 | 更新 nodeName（改进：nodeSelector） |
| ③ | 重新启动后仍秒退 | kit 校验和未随 driver 更新重新生成 | 重新生成 protocol.sha256 |
| ④ | 汇总失败 | sync Pod 无 python3 | 改由最后批次末尾执行汇总 |
