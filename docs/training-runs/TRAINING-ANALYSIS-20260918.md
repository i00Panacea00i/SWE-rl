## 二、数据集难度分析（回答"是否是 Easy 档"）

### 2.1 客观指标对比（我们的 21 题 vs SWE-bench Verified 各档）

| 维度 | **我们的 tier-0 池** | Verified **Easy** | Verified Medium | Verified Hard |
|---|---|---|---|---|
| 平均改动文件数 | **1.0** | 1.03 | 1.28 | 2.0 |
| 平均改动行数 | **5**（中位 6，范围 1-9） | **5.04** | 14.1 | 55.78 |
| 单文件占比 | 100% | 96.9% | — | — |
| 难度标注 | 无（tier=**仓库测试速度**分层，非难度） | OpenAI 人工标注 | 同左 | 同左 |
| 数据源 | SWE-Gym（训练集） | SWE-bench Verified（**评测集**） | | |

**结论 A**：在**改动规模**维度，我们的题**就是 Easy 档水平**（1 文件 / 5 行，几乎完全吻合）。

### 2.2 但为什么实测成功率差 100 倍？

| | 我们的题（7B 实测） | Verified Easy（公开数据） |
|---|---|---|
| 最佳单系统解决率 | **0.7%**（7B） | **81.4%**（AgentScope） |

差异不在 patch 大小，而在**定位难度与任务性质**：

1. **定位成本不同**：我们的题来自 mypy/conan/dask 等**大型代码库**——"改 5 行"意味着要在
   10 万+ 行代码中先找到那 5 行；Verified Easy 的题（如"给某函数加断言"）issue 描述往往
   直指位置
2. **仓库复杂度**：mypyc 编译器/类型系统、conan 构建系统——理解架构本身就是门槛
3. **SWE-Gym 的构建方式**：从 PR 反向构造训练题，不含"人工验证易解"过滤
4. **协议遵循损耗**：877 个 format_error 步——7B 的指令遵循能力在浪费宝贵的 turn

### 2.3 关于用 Verified Easy 做训练数据的风险提示

⚠️ **SWE-bench Verified 是标准评测集**。直接在其 Easy 档（194 题）上训练会导致：
- 后续在 Verified 上的评测分数**不可比**（训练污染）
- 缓解方案：训练后用 SWE-bench Full 中非 Verified 的实例评测；或明确标注"训练于 Easy 194"

## 三、H20×2 升级方案（回答"能否升级模型"）

### 3.1 硬件对比

| | L20（当前） | H20 ×2（可用） |
|---|---|---|
| 显存 | 48GB ×1 | **96GB ×2 = 192GB** |
| FP16 算力 | ~119 TFLOPS | ~148 TFLOPS ×2 |
| 可训模型上限（LoRA colocate） | 7B（14B 极限） | **32B 舒适 / 30B-MoE 可行** |

### 3.2 候选模型评估

| 模型 | 权重 | H20×2 可行性 | 参考依据 |
|---|---|---|---|
| **Qwen2.5-Coder-14B** | 28GB | ✅ 极舒适（tp=2 或单卡） | 本项目 pilot 中**唯一产生过非零奖励**的模型（django-11039） |
| **Qwen2.5-Coder-32B** | 64GB | ✅ 可行（2 卡分摊 32GB/卡） | 代码能力大幅跃升，SWE-bench 量级适合 |
| Qwen3-Coder-30B-A3B (MoE) | 66GB | ✅ 可行（激活仅 3B，推理快） | MoE 推理成本低，适合 RL rollout |
| Qwen3.5-9B（多模态） | 19GB | ✅ 轻松（此前 L20 上是极限操作） | 新代际，但架构适配成本已在上一轮验证 |

### 3.3 建议（按优先级）

1. **数据**：换用"定位容易"的题——两条路线：
   - a) **SWE-bench Verified Easy 194 题**（需接受污染声明；镜像大概率可从
     `xingyaoww/sweb.eval.x86_64.*` 获取，需验证 194 题覆盖度）
   - b) **保持 SWE-Gym** 但按"issue 描述含具体符号名/文件路径"二次筛选（无污染，工程量小）
2. **模型**：**Qwen2.5-Coder-14B**（首选，已验证有信号）或 **32B**（激进，能力上限更高）
   - 14B 在 H20 单卡即可运行：显存舒适后可去掉 `free_cache_engine`/逐单元导出等
     L20 时代的极限操作，训练更稳更快
3. **协议强化**（低成本高收益）：877 个 format_error 说明动作格式仍是短板——
   可在 system prompt 中加入 1-2 个 few-shot 正确格式示例（不改任务难度语义）
4. **训练规模**：模型升级 + 简单题后，预期成功率可从 0.7% 提升到 10-40% 量级，
   GRPO 信号组频率同步提升 10×+
