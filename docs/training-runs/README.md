## 2. 阶段叙事（汇报口径）

**阶段 A · 基础设施与冒烟（09-09 ~ 09-10）**
从零搭建东京 VPC / TKE 集群 / CFS 存储 / NAT 出口；AGS 沙箱平台打通
（12 题双向验证 11/12 通过，1 题 flaky 被正确识别）。

**阶段 B · 探索期：打通管道 + 修复判分器（09-11 ~ 09-14，4 次运行）**
核心矛盾：**判分器**（面对模型产出的海量坏补丁）必须"记 0 分而非崩溃"。
经历"全零奖励诊断 → 判分器击穿 → 有信号未更新"完整失败链后，
用**三级降级 + 隔离回放**关闭该问题线——这是后续一切成果的地基。

**阶段 C · 突破期：数据切换 + 模型升级（09-17 ~ 09-19）**
7B 能力瓶颈（0.7% 成功率）→ 9B 多模态选型失误（战略放弃）→
**30B-MoE + 4×L20 完整跑通 50 步**（奖励 0.042→0.119，+183%）。
关键工程：镜像覆盖（配额 28→1）、350Gi 内存配置、可续训检查点。

**阶段 D · 验证期：把"有没有用"测清楚（09-20 ~ 09-21）**
评估路径从 verl 共卡架构改为**独立 vLLM driver**（消除结构性 OOM）；
双协议对照：主协议（greedy）与副协议（4 采样）。
结论（诚实）：**50 步 LoRA 未带来可测提升**——但拿到了比结论更重要的
诊断数据：85% 的题模型 4 次全败（无训练信号源），pass@4(15%) 是 pass@1(5%)
的 3 倍（"会做但不稳"）。
