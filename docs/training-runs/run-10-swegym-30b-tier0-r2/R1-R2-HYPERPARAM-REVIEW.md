>
> **两轮定位**：r1 = 基建验证（"能训"）；r2 = 信号修复（"有效训"）。

| 项 | r1（run-07） | r2（run-10） |

## 1. 超参数对比表

### 1.1 优化器与更新策略（两轮**保持不变**的部分）

| 参数 | r1 实测值 | r2 实测值 | 变化 |
|---|---|---|---|
| 优化器类型 | AdamW（`torch.optim`） | AdamW（`torch.optim`） | 不变 |
| betas | [0.9, 0.999] | [0.9, 0.999] | 不变 |
| 权重衰减 weight_decay | 0.01 | 0.01 | 不变 |
| 学习率调度策略 | `constant`（恒定，无衰减） | `constant` | 不变 |
| 预热（warmup） | 无（steps=-1，ratio=0.0） | 无 | 不变 |
| LoRA 配置 | r=32 / α=64 / [q,k,v,o] / dropout 0 | 同 | 不变 |

> **要点**：优化器家族（AdamW）、权重衰减、调度策略**两轮完全一致**——两轮效果差异**不能归因于**优化器类型或正则化设置。这是一个干净的控制变量，使学习率、`clip_grad`、KL 系数三项的变化可被单独讨论。

### 1.2 学习率与梯度控制（**有变化**）

| 参数 | r1 | r2 | 变化 | 变更意图 |
|---|---|---|---|---|
| 学习率 lr | **1e-5** | **3e-5** | **×3** | 加快策略更新速度（低信号场景下避免"更新不足"） |
| 梯度裁剪 clip_grad | **1.0**（verl 默认，未显式设置） | **0.5** | **÷2** | 显式收紧——压制梯度爆炸（r1 实测爆炸至 8.011） |
| KL 系数 kl_loss_coef | 0.001 | 0.0005 | **÷2** | 放松对参考模型的偏离约束（配合更大 lr） |

### 1.3 采样与批量（**有变化**）

| 参数 | r1 | r2 | 变化 | 说明 |
|---|---|---|---|---|
| train_batch_size（题/步） | 8 | 8 | 不变 | 保持 8 题/步（成本控制，16 会令时长翻倍） |
| PPO mini batch | 8 | 8 | 不变 | — |
| 每题采样数 n | **4** | **8** | **×2** | 组内对比信号捕获概率提升（GRPO 的核心） |
| 名义轨迹/步 | 8×4 = 32 | 8×8 = 64 | ×2 | — |
| async 实际生成/步 | 32（同步模式） | 64–160（含重采样，filter 后入训约 90/步） | — | r2 异步生成 + 全零组淘汰 |
| filter_groups | 无 | **enable=True，max 3 gen batches** | 新增 | 淘汰全零梯度组（r2 实测 evicted 1.4–3.7 条/步） |

### 1.4 上下文与预算（**有变化**）

| 参数 | r1 | r2 | 变化 | 变更意图 |
|---|---|---|---|---|
| max_response_length | 8192 | **16384** | ×2 | 消除截断（r1 截断率 12.1%） |
| max_model_len | 16384 | **32768** | ×2 | 为长轨迹留空间 |
| max_num_batched_tokens | 8192 | **16384** | ×2 | 提升批效率 |
| 交互轮数上限 | 12 | **16** | +33% | 给足"读→改→测"周期 |
| temperature | 0.7 | 0.7 | 不变 | 探索强度保持 |

### 1.5 训练规模与调度（**有变化**）

| 参数 | r1 | r2 | 变化 |
|---|---|---|---|
| total_training_steps | 50 | **70** | +40% |
| val_before_train | True | False | 省一次启动评估 |
| test_freq（val 频率） | 5（运行值） | 25 | r1 更密（小 val 集成本低） |
| save_freq | 5 | 5 | 不变（每 5 步 LoRA-only 存档） |
| Agent workers | 10 | 16 | +60%（吞吐支撑） |
| gpu_memory_utilization | 0.5 | 0.5 | 不变 |

### 1.6 数据与提示词（**非超参数，但影响最大**）

| 项 | r1 | r2 | 说明 |
|---|---|---|---|
| 训练题池 | 20 题（tier0 全量） | **40 题（画像筛选：只留有学习信号的题）** | 消除全零梯度步的决定性变更 |
| 提示词 | 无行动纪律 | **读≤3 次必须编辑 / 禁重复命令 / 提交前验证** | 治"只读瘫痪" |
| 解析器 | 宽容解析（r1 中途修复） | 收紧 + 提交须有实际改动 | 消除幻觉提交 |
| 每步数据分布 | 20 题池循环抽取 | 40 题池，均匀覆盖 | 多样性 ×2 |

### 1.7 完整变更清单（一句话版）

```
数值超参数 4 项：lr ×3（1e-5→3e-5）、clip_grad ÷2（1.0→0.5）、kl ÷2（0.001→0.0005）、n ×2（4→8）
预算 4 项：response ×2、model_len ×2、batched_tokens ×2、轮数 +4（12→16）
规模 3 项：步数 +40%（50→70）、workers 10→16、filter_groups 新增
数据/提示词 2 项：题池 20→40（画像筛选）、行动纪律 prompt
保持不变量：优化器 AdamW / betas / weight_decay 0.01 / constant 无 warmup / LoRA r32 / batch=8 / temperature 0.7
```

## 2. 训练效果对比

> **指标口径说明（RL 与监督学习的差异）**：RL 训练没有"最小化损失"的目标语义——`pg_loss` 不衡量拟合优度，其波动（甚至为负）属正常现象。本复盘用四个维度替代传统曲线：**策略损失族**（pg_loss / KL / entropy / grad_norm）、**训练准确率**（奖励与通过率）、**收敛速度**（奖励爬升斜率 + 资源效率）、**过拟合/欠拟合**（训练内 vs 独立评估的落差）。全部数字来自两轮归档 metrics 与训练日志，同口径计算。

### 2.1 损失曲线族（策略健康度）

**策略损失 pg_loss（= actor/loss）段均值**：

| 步段 | r1 | r2 |
|---|---|---|
| 1-10 | +0.0558 | +0.0551 |
| 11-20 | −0.0030 | +0.1429 |
| 21-30 | +0.0106 | +0.1378 |
| 31-40 | +0.0098 | +0.0859 |
| 41-50 | +0.0053 | +0.0718 |
| 51-60 | —（无此步段） | +0.1006 |
| 61-70 | — | +0.0783 |

**解读**：
- r1 的 pg_loss 在前 10 步后即塌缩到 ≈0（±0.01）——**不是"收敛"，是梯度信号消失**（组内零方差、优势值全为 0 的结构性表现）；
- r2 的 pg_loss 维持在 0.06–0.14 的**活跃区间**（有正有负的波动），说明每一步都有可用的策略梯度——这正是"信号修复"的直接证据；
- 两轮 `pg_clipfrac` 均为 **0**——PPO 比率裁剪从未触发（策略更新幅度安全，未见激进漂移）。

**KL 散度（对参考模型的偏离）与策略熵（探索度）**：

| 指标 | r1（50 步） | r2（70 步） | 语义 |
|---|---|---|---|
| KL loss | 0.0052 → 0.0055（**平**） | 0.0043 → 0.0278（**升 6.5×**） | r1 策略几乎不动；r2 策略持续偏移并学习 |
| entropy | 0.377 → 0.419（**微升**） | 0.377 → **0.150（降 60%）** | r1 探索未收敛；r2 策略逐步确定化（学会稳定解法） |
| grad_norm 常态 | 0.023–0.024 | 0.030 → 0.067（缓升） | 均处健康区间 |
| grad_norm 极值 | **8.011（step 44，爆炸）** | **0.0786（step 64）** | clip_grad 0.5 的压制效果 |

**梯度爆炸对比（关键**）：r1 在 step 41/44/45 出现梯度范数 >0.5 的异常（峰值 8.011，约为常态的 300 倍）；r2 全程 70 步梯度范数**未超过 0.079**——`clip_grad=0.5` + 更高 lr 的组合下反而更稳定（梯度截断上限收紧后，更新方向更可控）。

### 2.4 过拟合 / 欠拟合表现

**判据：训练内提升 vs 独立评估（40 题 heldout，与训练题池零重叠）**：

| | r1 | r2 |
|---|---|---|
| 训练内奖励（MA 口径） | 0.130 → 0.127（持平） | 0.264 → 0.580（+120%） |
| 独立评估 pass@4 | 15% → **10%（−5pp）** | 15% → **17.5%（+2.5pp）** |
| 轨迹级通过率（评估） | 5.0%（8/160） | **7.5%（12/160）** |
| f2p 均值（评估） | — | 0.0697 → **0.0936（+34%）** |
| 判定 | **欠学习 + 轻微损害泛化** | **题池内适应 + 泛化初步改善** |

**结构性解读**：
- r1 属于**罕见的"双向失败"**：训练内几乎没学到（奖励持平），却把评估能力从 15% 拉低到 10%——低信号密度下的更新更多是噪声扰动而非有效学习；
- r2 呈现**健康的"学习型落差"**：训练内 0.580 与评估 0.175 仍然落差大，说明能力提升目前主要发生在**训练题池内**（40 题已接近饱和的迹象），泛化只显现出小幅正向——这是下一轮扩大题池的直接依据；
- 统计边界（诚实声明）：40 题样本下 ±1 题 = ±2.5pp，r2 的 +2.5pp 处于**噪声边缘**——"**不再损害 + 轻微改善**"是可靠结论，"显著跃升"尚不成立。

## 3. 差异分析：哪些调整起了关键作用

> **方法论前提（诚实声明）**：r2 同时变更了 13 项参数，且数据/提示词与超参数同批变化——**严格的单变量归因不成立**。本节采用"证据强度分级"：将每项变更与可观测的中间变量（截断率、只读率、梯度范数、evicted 数等）直接对照，分为 **决定性 / 直接可证 / 协同贡献 / 存疑** 四级。

### 3.1 决定性因素：数据筛选（题池 20 → 40，画像筛选）

**证据**：r2 第一步奖励即达 0.269–0.336（r1 首步 0.125），**起点高 2.1–2.7 倍**——这是"选对题"的直接效果，与任何超参数无关。
**机理**：r1 的 20 题池中 85% 的题对模型"超纲"（4 次采样全败 → 组内零方差 → 无梯度）；画像筛选后的 40 题保留了有学习信号的题，使**每一步都有正负样本对比**。
**结论**：**这是 r2 效果提升的第一贡献项**——它决定了"训练信号是否存在的下限"，其余超参数只在此下限之上放大效果。

### 3.2 直接可证的因素（有清晰中间变量）

| 变更 | 中间变量证据 | 效果 |
|---|---|---|
| **prompt 行动纪律** | 只读率 51.7% → 11.9% | 治"只读瘫痪"（r1 最大行为缺陷）|
| **response 8192 → 16384** | 截断率 12.1% → 1.0% | 消除"话说到一半被掐断" |
| **clip_grad 显式 0.5** | 梯度范数峰值 8.011 → 0.079 | 消除梯度爆炸（r1 在 step 41/44/45 实际发生）|
| **轮数 12 → 16 + 解析器收紧** | format_error 21.6% → 2.9%；submit 收尾 215 → 2352 条 | 完整"读→改→测→提交"周期 |
| **filter_groups 新增（async 路径）** | evicted 1.4–3.7 条/步（真实生效） | 全零组被淘汰，等效进一步提升信号密度 |

> **重要订正**：09-23 的静态代码核查曾判断 `filter_groups` 在 verl 0.10.0.dev 中"零实现"——**该结论只对同步路径（ray_trainer.py）成立**。r2 实际运行于 **async 训练路径（TaskRunnerV1 + replay_buffer）**，该路径存在完整实现，日志中 `training/filter_groups/evicted_samples` 逐步骤有值——机制**真实生效**。原判断已作废。

### 3.3 协同贡献因素（方向正确但单独贡献难分离）

| 变更 | 分析 |
|---|---|
| **lr 1e-5 → 3e-5（×3）** | r1 的问题是"更新不足"（kl 平、entropy 不降、奖励无趋势）；r2 的 kl 从 0.004 升到 0.028——更高 lr 让有效梯度真正转化为策略移动。但需与 n=8、数据筛选、kl 减半协同解释：**若没有组内信号，3e-5 只会放大噪声** |
| **kl_loss_coef 0.001 → 0.0005（÷2）** | 放松偏离约束，配合大 lr 使用；r2 的 kl 上升至 0.028 仍在安全范围（未跑飞）——两轮组合（lr ×3 + kl ÷2）等效"更新许可"放大 6 倍，被 clip_grad 0.5 兜底（全程无爆炸） |
| **n 4 → 8（×2）** | GRPO 组内对比的采样密度翻倍，全零组概率下降；与 filter_groups 叠加形成"防零梯度"双保险 |
| **async 生成 + workers 10 → 16** | 单步可容纳更多采样（64–160 条），支撑 n=8 与重采样；同时带来"训练越久越快"的效率收敛（2771s → 872s） |

### 3.4 存疑与未动用项（如实列出）

| 项 | 状态 | 说明 |
|---|---|---|
| batch 大小（8 题/步） | **两轮均未变** | 保持成本可控（16 会令时长翻倍）；当前证据不支持它成为瓶颈 |
| LoRA 容量（r32 / attention-only） | **两轮均未变** | 刻意控制变量；训练内 0.580 与泛化 0.175 的落差是否由容量上限造成——**尚无证据，留待第三轮实验** |
| 步数 50 → 70 | 变更有依据 | r2 到 step 70 未饱和（仍在上升）——70 步尚未榨干本轮提升空间；同时提示"继续加步数"有边际收益 |
| 新暴露：空补丁 28.2% | r2 新现象 | 模型学会了"提交"但部分提交为空——提示词/解析器下一轮需加"提交须含实际 diff"校验 |
| 统计噪声 | 评估 ±2.5pp | 40 题评估集的固有分辨率限制——见 §4 建议 |

### 3.5 归因结论（贡献度排序）

```
① 数据筛选（题池质量）      ——决定性：决定信号下限（起点 ×2.1–2.7）
② prompt 行动纪律 + 预算扩展 ——直接可证：消除三大行为缺陷（只读/截断/格式）
③ 梯度控制组合（clip 0.5 + lr ×3 + kl ÷2）——协同：让有效信号真正改变策略且不爆炸
④ n=8 + filter_groups 双保险 ——协同：压缩全零梯度步的发生概率
⑤ 步数 70（vs 50）           ——放大器：在信号健康的前提下多训 40%（且未饱和）
```

---

## 4. 结论与后续优化建议

### 4.1 核心结论（五条）

1. **优化器层面两轮完全一致**（AdamW / betas / weight_decay 0.01 / constant 无 warmup）——**效果差异与优化器选择无关**，全部来自学习率/梯度控制、采样、预算、数据与提示词四组变更；
2. **"信号密度"是被证实的核心变量**：r1 的问题不是学习率太小或优化器不好，而是**梯度信号结构性缺失**（pg_loss 塌缩到 0、奖励平台）；修复信号管道后（数据筛选 + prompt 纪律 + 预算 + n=8 + filter_groups），同一优化器配置即可产生单调上升的奖励曲线；
3. **梯度控制的组合拳有效**：`lr ×3 + kl ÷2 + clip_grad 0.5` 在"允许更大更新"与"压制爆炸"之间取得了平衡——r2 梯度范数峰值 0.079（r1 为 8.011），而学习速度提升显著，**"高 lr 必然不稳定"在本案中不成立**（前提是梯度先被 clamp）；
4. **泛化仍是最薄弱的环节**：训练内 0.580 vs 独立评估 0.175，落差虽较 r1 健康（方向正向），但 **40 题训练池的"题池内饱和"迹象已出现**（step 45 后斜率放缓）——继续在 40 题上训练将主要提升"记忆"而非"能力"；
5. **统计分辨率不足是结案短板**：40 题 heldout 的 ±2.5pp 噪声决定了"+2.5pp"无法被宣称为显著——**下一轮必须同步扩容评估集**，否则任何超参数实验都缺乏判定力。

### 4.2 后续优化建议（按优先级与可操作性）

| 优先级 | 建议 | 依据 | 预期收益 | 成本 |
|---|---|---|---|---|
| **P0** | **训练题池扩至 100+ 题**（保持画像筛选标准） | 40 题池已现饱和（训练内 0.58 vs 泛化 0.175）；r2 轨迹密度 39.8% 远超 r1（9.9%），说明筛选标准可复制放大 | 直击泛化瓶颈——唯一"训练内高、评估低"的解药 | 数据准备（筛选流水线已就绪）+ 时长 +40%（题池大不增单步耗时，仅增加总步数需求） |
| **P0** | **评估集扩至 100+ 题** | ±2.5pp 噪声使 r2 的正向提升处于"可见但不可宣称"状态 | 让"提升 5%/"与"持平"可区分——后续所有实验的判定力基础 | 评估时长 ~1 小时（已有流水线） |
| **P1** | **保留本轮全部配置作为基线**（数据筛选 / prompt 纪律 / 预算 / n=8 / clip 0.5 / kl 0.0005 / filter_groups） | 每项均有中间变量佐证（见 §3） | 避免"回退已证有效的变更" | 零 |
| **P1** | **LoRA 容量实验（单变量）**：r 32 → 64 | 0.088% 参数占比或已触及容量上限（训练内 0.58 与泛化的落差的一种可能解释） | 若容量是瓶颈：泛化同步改善；若不是：排除该假设（同等重要） | 训练+评估一轮；显存增量小（+53M 参数） |
| **P2** | **步数策略：不盲增**——题池扩容后按"奖励曲线出现平台"为准动态定步数 | r2 到 step 70 未饱和是**在 40 题池下**的结论；题池扩容后饱和点会前移/后移未知 | 避免无效训练时长 | 监控脚本（已有 metrics 流水线） |
| **P2** | **补丁行为修复**：提交前校验"非空 diff"（提示词 + 解析器双管） | 空补丁 28.2%（r2 新暴露） | 直接把 28% 的空提交转化为有价值的尝试 | prompt 一行 + 解析器小改 |
| **P3** | **学习率消融（备选实验）**：3e-5 vs 2e-5（若题池扩容后出现不稳定） | 当前 lr 是在"信号修复"同批变更——独立最优值未验证 | 优化更新效率 | 单变量一轮（成本高，非必要不做） |

### 4.3 下一轮的实验设计原则（从本轮教训凝练）

1. **单变量纪律**：本轮 13 项同改导致归因只能做到"证据分级"；第三轮应以"题池扩容 + 容量实验"两变量为主，其余冻结；
2. **评估先行**：先扩评估集（P0），再启动训练——否则新训练的结论仍将困在 ±2.5pp 的噪声里；
3. **口径统一**：所有对外数字使用可复现口径（本复盘 §2 的定义），并在文档中标注数据源与计算方法（本轮已发现 r1 早期报告存在平滑口径不一致的问题）。
