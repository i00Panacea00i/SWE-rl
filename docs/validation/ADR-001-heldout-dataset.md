# ADR-001：Held-out 测试集的构成与验证流程

- **状态**：已决定（2026-09-20）
- **决策者**：项目负责人（ interviewed）
- **背景文档**：`docs/troubleshooting/05-data-judging.md`（双向验证方法论）

## 背景

训练运行 `swegym-30b-tier0-r1` 使用 20 题训练 + 2 题评估——**22 道已验证题全部用尽，零剩余 held-out**。
候选池 86 题（tier0 35 + tier1 51）**从未通过双向验证**——直接用作测试集会让三类"毒题"污染指标：
- 假阳性题（baseline 直接过）→ 双方都"通过"，稀释 Δ；
- flaky 题（结果随机）→ 增加方差；
- 坏题（golden 都过不了）→ 纯噪声。

## 决策

1. **全量验证 86 题**（baseline×1 + golden×2，复用 `sandbox/validate_swe_ags.py` 镜像覆盖路径 + 自动重试）；
2. **通过验证的题全部进入测试集**（预期 ~70 题：tier0 ~30 + tier1 ~40，按历史 ~85% 通过率）；
3. **分层报告**：tier0（与训练同分布，测"提升"）与 tier1（更难，测"泛化"）分开统计；
4. **防泄漏双检查**：
   - 测试集 ∩ 训练集（20 题）= ∅（构建时断言）；
   - 测试集 ∩ 训练期评估集（mypy-15131 / conan-14177）= ∅。

> **实战记录（2026-09-20）**：首次执行即拦截 **1 个泄漏题**（`conan-14397`）——根因是**候选清单快照漂移**：该题在候选清单生成时尚未验证，之后通过验证并进入了训练集，但清单未同步。构建脚本已升级为**泄漏题自动剔除 + manifest 留痕**（`failure_mode=leak_with_train_set`）。
> **教训**：候选清单必须以"**使用时刻**"的训练集为准做动态校验，不信任生成时的排除逻辑。

## 流程（无 GPU 阶段，可立即执行）

```
候选池 86 题（/tmp/expand-todo.jsonl + data/swe-gym-instances-tcr.jsonl）
  │ ① 镜像预热（86 个，CreatePreCacheImageTask）
  │ ② 双向验证：baseline×1 + golden×2，并发 10，自动重试（409/preparing → 重试）
  │ ③ 剔除：baseline_pass / flaky / f2p_fail（记录剔除理由，留痕）
  ▼
测试集冻结（~70 题）
  │ ④ 产出：validation/heldout-manifest.json（题目清单 + 剔除记录 + 校验和）
```

预计耗时：预热 <5 分钟 + 验证 1~2 小时。

## 后果

- **正面**：指标可信（无假阳性稀释、无坏题噪声）；分层证据（提升 + 泛化两问全答）；全部过程可审计（每题留验证轨迹）。
- **负面**：+1~2 小时准备时间；部分候选会被剔除（预期 10-15 题），实际样本量低于 86。
- **风险**：若剔除率显著超预期（>30%），说明数据集质量或镜像/平台存在系统问题——此时暂停并复盘（参照 `05-data-judging.md §3.3` 的"暂时性 vs 质量"区分），不得带着脏数据开测。
