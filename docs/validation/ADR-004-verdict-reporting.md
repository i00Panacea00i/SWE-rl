# ADR-004：判定标准与报告纪律（预注册）

- **状态**：已决定（2026-09-20）—— **开测前锁定，测试后不得修改**
- **前置**：[ADR-001](ADR-001-heldout-dataset.md) / [ADR-002](ADR-002-pass1-protocol.md) / [ADR-003](ADR-003-eval-infrastructure.md)

## 背景

"测完再定什么叫更好"是实验报告最常见的作弊。本 ADR 在**任何数据产生之前**锁定判定口径与报告内容，防止事后挑选。
用户选定**宽松判定**（Δ>0 即认可）——本 ADR 如实记录该决策，并附加**不可协商的透明度条款**。

## 决策

### 1. 判定口径（用户选定）

| 结果 | 判定表述 |
|---|---|
| Δresolved > 0 | **认可为"有提升"**（在报告显著位置披露统计力限制） |
| Δresolved ≤ 0 | **"无提升"，如实报告**（不得粉饰、不得隐藏） |

> ⚠️ **决策者已知悉的保留意见**（记录在案）：宽松口径下 Δ=+1pp（70 题差 1 题）亦可叙述为"提升"，但置信区间必然含 0。此风险由下述第 2 条的强制披露条款对冲。

### 2. 透明度条款（不可协商，任何报告必须包含）

无论判定口径，**最终报告必须给出全套统计量**：

1. **Δresolved**（LoRA − base，百分点）——主指标 temp0；
2. **Wilson 95% 置信区间**（两个比例 + Δ 的区间）；
3. **McNemar 检验 p 值**（配对 2×2 表：only-base / only-LoRA / both / neither）；
4. **分层结果**（tier0 / tier1 分列——提升与泛化分别回答）；
5. **副协议结果**（temp0.7×4 的 pass@1 与 best-of-4）；
6. **协议质量对照**（format_error / 有效操作数 / 平均轮数——两组的"做题过程"差异）。

**表述纪律**：
- Δ>0 **但 p ≥ 0.05** → 必须写明"**方向性证据，未达统计显著**"；
- Δ>0 **且 p < 0.05 且 Δ ≥ 10pp** → 可表述"**显著提升**"；
- Δ>0 **且 p < 0.05 但 Δ < 10pp** → "**统计显著的小幅提升**"；
- Δ≤0 → "**无提升**" + 根因分析章节（训练不足 / 超参 / 数据 / 采样方差）。

### 3. 报告结构（固定模板）

```
reports/eval-30b-base-vs-lora/
├── README.md            # 结论摘要 + 判定 + 全套统计量 + 图表
├── figs/
│   ├── pass1_comparison.png    # 双组 pass@1 柱状 + CI
│   ├── per_tier.png            # 分层对比
│   └── concordance.png         # McNemar 2×2 + 散点（按题对）
├── metrics/             # CSV：逐题结果、聚合统计
└── REFERENCE.md         # 轨迹/日志/复现指引
```

### 4. 受众与发布

- **归档三副本**：本地 + CFS + COS（沿用归档协议）；
- **GitHub**：追加至本仓库 `reports/`（公开）——结论表述遵循第 2 条纪律；
- **内部**：完整原始数据（含未过审题目的剔除记录）随 CFS 归档。

### 5. 失败预案（预注册）

| 场景 | 预案 |
|---|---|
| val-only 模式不可用 | 启用 [ADR-003 §2](ADR-003-eval-infrastructure.md) 备选；结论交叉核对 |
| 资源窗口不足（只够主协议） | 主协议先行出结论；副协议标记"延后"（报告中注明） |
| 测试集剔除率 >30% | 暂停，复盘数据/平台（ADR-001 风险条款） |
| 结果 Δ≈0 且 p 无意义 | 如实报告 + 根因分析；**这本身是有效科学产出**（回答"训练是否有效"） |

## 后果

- **正面**：预注册不可事后修改 → 结论可信度最高；宽松判定 + 透明度条款兼顾"认可进步"与"统计诚实"。
- **负面**：报告中"方向性证据，未达统计显著"的措辞可能不够"漂亮"——接受。
- **红线**：任何删改统计量、隐藏负结果、把 p≥0.05 包装成"显著"的行为——禁止。
