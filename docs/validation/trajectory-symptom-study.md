# 轨迹症状学研究：20 案例深读 + 1692 条全量分类

> **方法**：分层抽样 20 个不同 case 深读（行为指纹 + 轮次原文）+ 全量 1692 条自动归类
> **目的**：建立失败模式分类学——从"症状"层回答"训练为什么没效果、该治哪里"
> **数据**：`artifacts/archive/cfs-traces-30b/traces/swegym-30b-tier0-r1/train/`（1692 条）
> **日期**：2026-09-22

---

## 0. 结论速览

**核心发现：50.6% 的算力消耗在"说而不做"的轨迹上**（S1+S2+S3），
加上 token 截断（S5）合计 **61.7% 的轨迹没有进入"有效编辑"状态**。

| 簇 | 症状 | 规模 | 占比 | 一句话根因 |
|---|---|---|---|---|
| **S4** | 试错未成（有编辑，用尽步数） | 457 | **27.0%** | 方向错/效率低（诊断过长后仓促编辑） |
| **S2** | **只读瘫痪**（0 次编辑） | 426 | **25.2%** | 信息收集不收敛（读了 11 轮仍不敢动手） |
| **S3** | **散文主导**（≥50% 轮次格式错） | 365 | **21.6%** | 输出格式混乱（命令从未被正确解析） |
| **S5** | token 截断（有编辑） | 187 | 11.1% | 训练预算 8192 不足（评估侧 16384） |
| **S0** | ✅ 成功 | 163 | 9.6% | 2-5 轮内进入编辑 + 验证通过 |
| **S1** | **幻觉提交**（submit 但 0 补丁） | 65 | 3.8% | 模型宣布"测试通过"但实际从未修改 |
| S6b | 异常终止（无终态） | 19 | 1.1% | 中途失败 |
| S6a | 启动失败（空 episode） | 10 | 0.6% | 沙箱创建失败 |

## 1. 研究方法

### 1.1 分层抽样（20 case，覆盖矩阵）

```
5 成功（不同 step 分散） + 3 f2p 部分 + 4 有补丁但 0 分 + 5 空补丁 + 3 特殊（格式/空/无终态）
```

### 1.2 行为指纹编码（每个 case 一行，症状一目了然）

```
字母：E=执行 I=读代码 T=测试 D=编辑 F=格式错 S=提交    数字：exit_code
例："T1 I0 I0 D0 T0"  = 测试失败 → 读2次 → 编辑 → 测试通过
```

### 1.3 互斥归类规则（每条轨迹归入首个命中的簇）

`S6 启动/异常 → S1 幻觉提交 → S3 散文主导 → S2 只读 → S5 截断 → S0/S4（按 resolved 分）`

## 2. 六大症状簇详解

### S0 · 成功（163 条，9.6%）——成功轨迹的解剖

**指纹共性**：`T1/I0 开头 → 2~5 轮内首次编辑 → 验证（T0）→ submit`

**成功组的首编辑轮次分布**：`{2: 48, 4: 24, 5: 20, 6: 15, 7: 14, 8: 21...}`——中位 **第 5 轮**。

**意外发现**：成功轨迹**也带格式税**——如 `step-40/mypy-10683` 的一条成功轨迹含
**3 次 exit 127 + 1 次 exit 2**（12 轮里 4 轮格式问题）——**格式错误是基础税，不是判决**。

### S1 · 幻觉提交（65 条，3.8%；占全部 submit 的 **30%**）

**定义**：`stop_reason=submit` 且 `candidate.patch=0`——**模型宣布完成，实际什么都没改**。

**标本**（`step-30/mypy-11434`，5 轮，stop=submit）：
```
[4] "my previous fix attempts didn't work correctly and may have..."（承认之前没改对）
[5] "The tests are now passing! My fix has resolved the issue. Let me run a broader test..."
→ submit        ← 对着"从未被修改的工作区"宣布成功
判分：patch=0B / reward=0 / f2p 0/2
```

**轮次分布** `{3:4, 4:6, 5:3, 6:5, 7:6, 8:13, 9:9, 10:7, 11:4, 12:8}`——**不是草率早停**
（中位 8 轮）——模型"认真工作后真诚地产生了成功幻觉"——**认知与现实脱节**。

### S2 · 只读瘫痪（426 条，25.2%——最大单簇）

**定义**：全程 0 次编辑（`inspect`/`test` 主导）。

**标本**（`step-30/mypy-11434` 另一采样，12 轮纯读）：
```
[1] T1  [2-11] I0 ×10（"Let me examine...", "Let me see more...", "Now I need to find..."）
[12] "I think the issue is that when we have a TypeVar with a bound TypedDict..."
→ step_budget 用尽，patch=0
```

**特征**：模型**每轮都在"更深入地理解"**（语言上逐步逼近根因），但**从不尝试修改**——
"分析瘫痪"（analysis paralysis）。**与 S1 的关系**：持续只读的终局往往是
"步数耗尽"（S2）或"幻觉提交"（S1）——**同一个病的两种结局**。

### S3 · 散文主导（365 条，21.6%）

**定义**：≥50% 轮次为格式错误（exit 2 语法拦截 / exit 127 散文被执行）。

**标本**（`step-0/mypy-15131` s2bf9db05，12 轮）：
```
指纹：E2 E2 E127 E2 E2 E127 T127 E2 E127 E127 E127 E127
[1] "Looking at the issue, I need to understand what's happening. The error message says..." → exit 2（引号未闭合）
[3] "Let me check what files are available..." → 127
...12 轮里 0 次成功命令
```

**同题同 step 的极端对照**（最震撼的证据）：
```
step-0/mypy-15131  s?（成功）: T1 I I I D I E127 → 7 轮 submit → reward=1.0（patch 865B）
step-0/mypy-15131  s2bf9db05: E2 E2 E127 ×12 → patch=0 → reward=0
```
**同一道题、同一个训练步、同温度**——一条 7 轮解决，一条全程无法执行任何命令。
**这是方差（variance）的最极端展示**，也是"格式稳定性"直接影响成败的铁证。

### S4 · 试错未成（457 条，27.0%——最大簇）

**定义**：有编辑动作，但用尽步数仍未通过。

**标本**（`step-23/mypy-15159`，12 轮，2 次编辑均 x1）：
```
[1-9] T1 + I0 ×8（诊断 9 轮）  ← 诊断占比 75%
[10] edit x1（"Now I see the expected behavior..."）
[11] edit x1（"Let me fix this more carefully: sed -i '1112,1120s/...'"）  ← 仍是 sed 直接替换
[12] "Let me approach this differently with a simpler one-line fix..." → 步数耗尽
```

**特征**：**诊断过长（8-9 轮）→ 剩 2-3 轮仓促编辑 → 方向错**。
与成功组的差异不在"是否努力"，而在**节奏**（成功组第 5 轮前已开始验证式编辑）。

### S5 · token 截断（187 条，11.1%）

**定义**：`stop_reason=token_budget` 且已完成过编辑——**改到一半被预算砍断**。

**证据链**：训练预算 `max_response_length=8192` vs 评估侧 `16384`——
全局 419 条（24.8%）被 token 截断（含未及编辑的），**是评估侧（1.9%）的 13 倍**。

### S6 · 启动/异常（29 条，1.7%）

- **S6a 空 episode**（10 条）：`steps=0`——rollout 启动即失败（沙箱创建异常）；
- **S6b 无终态**（19 条）：`stop_reason=None`——中途异常（如 2 轮后消失）。

## 3. 横切发现（症状学规律）

### 3.1 "说而不做"是系统性核心病症
S1（幻觉提交）+ S2（只读瘫痪）+ S3（散文主导）= **50.6%**——
**一半算力消耗在"没有产生任何有效修改"的轨迹上**。这不是个别题的问题，
而是**行为模式层面的系统疾病**。

### 3.2 编辑时机与成功的强关联
| 组 | 首编辑时机 | 解读 |
|---|---|---|
| 成功（178 条有编辑） | 中位第 5 轮，**48 条第 2 轮** | 先快速诊断 1-4 轮 → 动手 → 迭代验证 |
| 失败（685 条有编辑） | 中位第 6 轮，**但两端分布**：第 1 轮 76 条 / 第 11-12 轮 67 条 | **太早**（无诊断瞎改）与**太晚**（读 11 轮才动手）都失败 |

**"编辑过的轨迹"成功率 20.6%（178/863），未编辑的结构性 0%**——
**治疗重点应是"让模型在第 2-5 轮进入编辑"**。

### 3.3 同题方差巨大（最反直觉的发现）
同题同 step 同温度：一条成功、一条全格式灾难（§S3 对照）。
**含义**：当前策略的方差远大于训练带来的均值提升——**这解释了为什么 50 步训练
测不出效果**（噪声 > 信号）。降方差（格式稳定性、收尾纪律）本身就是提升。

### 3.4 症状的时间演化
S3（散文率）从早期 ~29% 缓慢降至 ~15%（step-2 → step-50）——**有改善但未质变**；
S2（只读）无显著时间趋势——**行为病症不会随步数自愈**。

## 4. 对训练的启示（按 ROI 排序）

| 症状 | 对策 | 预期 |
|---|---|---|
| **S2 只读（25.2%）** | ① prompt 行动纪律（"读 3 次内必须尝试编辑"）；② **难度筛选**（读不懂的题直接剔除） | 减半以上 |
| **S3 散文（21.6%）** | 解析器收紧：无完整 bash 块 **直接拒绝**并回送格式提示（当前宽容解析产生 10.4% 的无效执行） | 消除大半 |
| **S4 试错（27.0%）** | 数据筛选（可学习区间）+ lr ×10 / all-linear（提升每次编辑的有效性） | 部分转化为 S0 |
| **S5 截断（11.1%）** | 预算 8192 → 16384（与评估对齐） | 消除 |
| **S1 幻觉提交（3.8%）** | submit 动作要求附带"本次改动的文件清单"（无改动即拒绝提交） | 消除 65 条无效提交 |
| S6（1.7%） | 沙箱创建重试机制 | 减半 |
