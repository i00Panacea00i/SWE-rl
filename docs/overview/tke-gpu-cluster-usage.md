# TKE GPU 集群使用报告（训练与评估）

> **汇报要点**：本项目在腾讯云 TKE 上以**单节点 4×L20**完成了 30B-MoE 模型的
> 完整 RL 训练（50 步 / 21 小时 / 1692 条轨迹），并用同一集群完成了两轮模型对照评估。
> 本报告给出**资源账、性能实测、运维要点与扩容论证**。

---

## 0. 速览（五个关键数字）

| 数字 | 含义 |
|---|---|
| **4×L20 = 192GB 显存** | 单节点训练全部所需（30B-MoE + LoRA 最小可行配置） |
| **21 小时 / 50 步** | 完整训练时长（含验证、检查点、一次故障恢复） |

## 2. 资源使用账（训练实测）

### 2.1 显存（每卡 44GB）

| 组件 | 占用 | 说明 |
|---|---|---|
| vLLM 权重分片（TP=4） | 15.3 GB | 61GB 模型 ÷ 4 卡 |
| vLLM KV cache（util=0.5） | ~7 GB | 上下文 16384 上限 |
| FSDP actor / ref | 分片后常驻 | `param_offload=True` 降峰值 |
| 训练峰值（实测） | ~26 GB/卡 | 余量健康，无 OOM |

### 2.2 内存（Pod limit 350Gi）——最关键的一处调参

| 阶段 | 配置 | 结果 |
|---|---|---|
| 初版 | 300Gi limit + 64Gi shm | ❌ **实测 OOM（286/300GB）** |
| 修复后 | **350Gi + 32Gi shm** + vLLM util 0.6→0.5 + agent workers 10→8 | ✅ 稳定，从 step 5 无损续训 |

内存构成：vLLM 备份（休眠期权重存 CPU）≈100GB + actor 61GB + ref 61GB + shm 32GB
+ Ray 对象存储 —— **经验公式：内存 ≈ 3× 模型大小**。

### 2.3 存储（CFS）

| 资产 | 大小 |
|---|---|
| 基座模型（16 分片） | 61.1 GB |
| 检查点 ×10（每 5 步，LoRA-only） | 166 MB/个 |
| HF adapter（最终） | 53.5 MB |
| 轨迹与判分证据 | 数 GB（1692 条训练 + 320 条评估） |

## 3. 训练性能（实测曲线）

| 指标 | step 6 | step 50 | 趋势 |
|---|---|---|---|
| 步耗时 `timing_s/step` | 840 s | 770 s | 趋稳（约 13 分钟/步） |
| 吞吐 `perf/throughput` | 53.1 | 61.9 | +16%（随输出变长） |
| 平均响应长度 | 4468 | 5115 token | 接近 8192 预算的 62%（**截断率 6-19%——见审计文档**） |
| 平均交互轮次 | 21.6 | 21.9 | 稳定 |

**训练总账**：50 步 × ~800s ≈ 11 小时纯训练 + 验证（每 10 步）+ 检查点（每 5 步）
+ 一次 CPU OOM 恢复 ≈ **21 小时**。

## 4. 集群运维要点（可复用的 6 条）

1. **调度**：单 GPU 节点 → `nodeName` 固定（本次教训：节点重建后需更新；建议 `nodeSelector`）；
2. **存储**：CFS 同 VPC 直挂（NFS PV）——模型/检查点/轨迹全部落在 CFS，Pod 可随时重建；
3. **凭证**：`tccli` oauth 凭证以 Secret 挂载（refreshToken 自动续期），供 AGS 控制面调用；
4. **镜像**：节点直拉（DockerHub + NAT 出网）；新节点首次拉取 12GB ≈ 15 分钟——**提前预热**；
5. **检查点策略**：LoRA-only 每 5 步（166MB/个）——任何中断从"灾难"降级为"插曲"（CPU OOM 实证）；
6. **资源下限**：内存 350Gi / shm 32Gi / vLLM util 0.5 / agent workers 8——低于任一值均有实录故障。

## 5. 瓶颈分析与扩容论证（H20×2）

| 维度 | 现状（4×L20 192GB） | 扩容后（2×H20 192GB） | 收益 |
|---|---|---|---|
| 单卡显存 | 44GB（30B 只能 LoRA） | **96GB** | 可全参微调 / 更大 batch |
| 可训模型 | 30B-MoE（LoRA 限定） | **32B 全参 / 70B LoRA** | 能力上限与稳定性 |
| 推理 KV 容量 | 受限（util 0.5） | 大幅提升 | 更长轨迹/更高并发 |
| 生态 | L20 通用 | H20（FP8 支持） | 吞吐与精度选项 |

**结论**：当前配置已把 30B-MoE + LoRA 推到工程极限（训练跑通、闭环验证完成）；
**下一步的能力跃升（全参、更大模型、更大采样）需要 H20 级显存**。

## 6. 经验教训（一页纸）

1. 单机训练的**内存需求 ≈ 3× 模型大小**（vLLM 备份 + 双模型 offload + shm）——按峰值算，留 15% 余量；
2. **可续训检查点**是长跑训练的第一保险（本次 OOM 恢复零损失）；
3. 节点不是永恒的——**清单不要硬编码节点 IP**；
4. 训练与评估用**同一套集群+存储**，数据零搬运（CFS 直挂）是效率关键；
5. 资源释放要及时（本项目评估完成后即刻清 Pod；节点退租在控制台完成）。
